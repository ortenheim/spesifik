# spesifik

**Spec-driven utvikling for norsk offentlig sektor.**

spesifik er et åpent rammeverk som binder spec, kode, tester og Azure DevOps i én lukket sløyfe — slik at KI-utvikling kan skalere uten å miste kontroll, sporbarhet eller regelverkstilpasning.

## Problemet det løser

KI-koding gir 10× output — og 10× teknisk gjeld. Spec og kode glir fra hverandre. ADO og fagansvarlig snakker forbi hverandre. Brukerhistorier tapes i overgangen til kode. GDPR og EU AI Act-arbeid skjer etter at koden er skrevet.

spesifik løser dette gjennom fire faser: **Forstå → Spesifiser → Bygg → Verifiser** — med toveis ADO-sync via MCP, en HTML-spec-artefakt som alle roller kan lese, og innebygde validatorer for sikkerhet og personvern.

## Metodikken kort

- **Spec som kontrakt** — SPEK.md er leselig for fagansvarlig, jus og sikkerhet. ADO er sannheten for utvikleren. spesifik holder dem synkronisert.
- **Roller og broer** — endrer ikke hva folk gjør, men hva de leverer til hverandre. Smertepunktene oppstår i overgangene, ikke i rollene.
- **HTML-spec-artefakten** — det eneste formatet som samler Figma-referanser, Markdown-spec, designtokens og ADO-oppgaver i ett gap-bevisst dokument.
- **Kunnskap blir igjen** — constitution, SPEK.md og ADO-strukturen eies av virksomheten, ikke konsulenten.
